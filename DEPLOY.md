# Deploying ExamMind to Render

`render.yaml` at the repo root is a Render Blueprint. It provisions three
resources and wires most of the configuration between them:

| Resource | Name | What it is |
| --- | --- | --- |
| Postgres | `exammind-db` | Managed database, `DATABASE_URL` injected into the API |
| Web service | `exammind-api` | FastAPI on uvicorn, from `backend/` |
| Static site | `exammind-web` | The Vite build, from `frontend/` |

## Read this first: three constraints on the free plan

**1. The embedding model needs more memory than the free instance has.**
`ai_clients.py` loads fastembed with `BAAI/bge-small-en-v1.5` through
onnxruntime at import. Model weights plus the ONNX runtime land around
400-600MB resident, and a free Render web service is capped at 512MB. Expect
the API to be OOM-killed on boot. Options, cheapest first:

- Move embeddings to a hosted API and drop fastembed from the import path.
- Upgrade `exammind-api` to a paid instance with 2GB.

Everything else here works on free; this is the one thing that probably will
not. Decide it before you spend time debugging a boot loop.

**2. Free Postgres is deleted after 30 days.** Render expires free databases.
Anything uploaded or indexed goes with it. Fine for a demo, not for a pilot with
real students.

**3. Free web services sleep after 15 minutes idle.** The next request pays a
cold start, and this one also re-loads the embedding model, so the first hit
after a quiet spell is slow rather than instant.

## Deploy

**1. Push the branch.** Render reads `render.yaml` from the branch you point it
at.

**2. New > Blueprint** in the Render dashboard, select this repository and the
branch. Render shows the three resources it is about to create. Apply.

**3. Fill in the secrets it could not generate.** On `exammind-api` > Environment:

- `DEEPSEEK_API_KEY` — the primary AI provider.
- `COHERE_API_KEY` — the fallback. Both are optional; without them the API
  still boots, uploads and search still work, and only the assistant answers
  degrade. The log says so plainly on startup.
- `OPENAI_API_KEY` — only if you switch `AI_PROVIDER`.

`SECRET_KEY` is generated by Render. `DATABASE_URL` is injected from the
database. Neither needs touching.

**4. Point the two services at each other.** This is the step the blueprint
cannot do for you, and getting it wrong is the most likely reason a deploy looks
up but does not work.

- Copy the API's URL, e.g. `https://exammind-api.onrender.com`.
- On `exammind-web` > Environment, set `VITE_API_BASE_URL` to that URL,
  **including `https://`**. Vite bakes this in at build time, so redeploy the
  static site after changing it — a restart is not enough.
- Copy the frontend's URL, e.g. `https://exammind-web.onrender.com`.
- On `exammind-api` > Environment, set `CORS_ORIGINS` to that URL. Comma-separate
  if you add more. No trailing slash — the origin must match exactly or the
  browser blocks every request with a CORS error while the API logs a clean 200.

**5. Check it.** `https://exammind-api.onrender.com/docs` should render the
FastAPI page. Then load the frontend and sign in.

## What the code does on first boot

`main.py` runs `_prepare_database()` at import:

1. `CREATE EXTENSION IF NOT EXISTS vector` — `models.py` maps a pgvector
   `Vector` column, and a freshly provisioned database has no extensions
   enabled, so `create_all` would fail on an unknown type.
2. `Base.metadata.create_all` — idempotent, safe every boot.

You do **not** need to run `init_db.py` or `migrate.py` on Render; those are the
local Windows path.

`database.py` rewrites the `DATABASE_URL` Render provides. Render hands out
`postgres://...`; SQLAlchemy needs an explicit driver or it reaches for psycopg2,
which is not in `requirements.txt` — this project installs psycopg 3. The
rewrite makes it `postgresql+psycopg://`.

## Local development

Unchanged, and documented in `README.md`. Two things worth knowing, both learned
the hard way:

- `backend/.venv` holds the Python dependencies. Activate it, or call
  `backend/.venv/Scripts/python.exe` directly, or you are running against a
  global interpreter that does not have them.
- If Postgres is not running, the API now fails in about ten seconds with
  `ConnectionTimeout` instead of hanging forever on the TCP connect. Previously
  uvicorn never bound its port and the frontend showed
  `ERR_CONNECTION_REFUSED`, which looks like a crashed backend rather than a
  missing database. Start Docker Desktop, then `cd backend && docker compose up -d`.
